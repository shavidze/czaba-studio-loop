## When writing a task (B)
1. **Inventory before grants.** If the task has a stop-on-inventory rule, B runs the same scan first: same line, multi-line `cn()`/arrays, constants defined on a later line, child icons. Test the scanner on one known-shape mutant, and cite the result in the task. For focus/visibility work, also scan for visually hidden focusables (`opacity-0`, `invisible`, `sr-only` on or around a tabbable element) and rule on each hit; confirm "is it rendered at all" with an import grep. A static scan misses runtime-hidden focusables (closed menus, scroll-reveal blocks): also run a browser Tab probe with ≥ 2 s settle at 375, 1280 and 1440 and list every stop at effective opacity 0. Probe backward entry too (End, then Shift+Tab), with keys ≥ 1.2 s apart (Lenis animates 1.2 s). Before blaming a scroll jump on smooth scroll, check for an auto-opening scroll-lock popup (LeadMagnet: 8 s after a 40 % scroll) and stub the suspect. Signed-in header UI is browser-testable with `localStorage.auth_user` without `accessToken` (no backend call); do not mark it BLOCKED-AUTH. Evidence: B-R192-PLANNING-GAP, B-R194-K0-SCAN-GAP, B-R200-HIDDEN-FOCUSABLE-GAP (rounds 192, 194, 201 lost); C-R202-04/05; B-R203-LEADMAGNET-AUTO-OPEN-FOCUS (1×).
2. **Token value change → consumer rows.** For every changed colour token, list each UI-boundary consumer (text, border, field, ring) as a measured contrast row, before dispatch. Evidence: C-R193-01/02, C-R194-01, B-R193-UNMEASURED-INFO.
3. **Text or font change → widest-state box rows.** For each changed string or font, add a row for its longest state (Playing, error, multi-select) at 1280×720 and 1440×900, with the old-language/old-font swap as the control. Evidence: C-R142-01, C-R143-01, C-R145-01, C-R151-2, C-R154-01.
4. **One element, one rule.** When two clauses can bind the same element (e.g. "panels ±1 px" and "own text may change"), the task says which wins. Evidence: C-R151-1 (spec conflict), C-R143-01.
5. **Scope as semantic changes, not line counts.** Do not write "exactly N changed lines" unless Biome's lineWidth (100) was checked on the result. Evidence: STORE2A-BUTTON-REFLOW / C-R193-03 (1×).
6. **Carry parked rows explicitly.** When planning a regression round, copy every `scope_additions` entry of the due `regression_rounds` item into a named row, or mark it "carried" in the task. Evidence: REG-DUX5-PLAYHEAD-RESCAN missed in round 199.
7. **Close what a later round fixed.** When a fix-up closes a bug, grep `deferred_low_polish` and `open_findings` for the same root cause and close or update those ids in the same planning. Evidence: A-R147-REVIEW-L2-BADGE-CLASS-SELECTOR stayed open 21 rounds after round 179 fixed it.
8. **A deferred Low on a test selector is a time bomb.** A Low that pins styling classes or source text is scheduled before the visual stage that changes those classes. Evidence: A-R147-REVIEW-L2 (deferred round 147) → C-R178-BADGE-SELECTOR (Medium, round 178 FAIL).
9. **Engine rounding.** Sub-pixel widths (1.5 px rings) are written with the measured Chromium result, or as "≥ 1 px painted". Evidence: C-R196-04 (1×).
10. **Rule on every STOP before re-dispatch.** When A reports a STOP, or C reports "B has not ruled", the next task carries the explicit ruling (accepted delta or changed criterion, with the finding id) before anything is re-dispatched. Evidence: C-R142-01, C-R143-01 (no `b-round-143*` ruling existed).
23. **Mandatory change vs frozen or protected file: grant or rule before dispatch.** For every mandatory item, grep its removed or renamed tokens and its new labels in `app/**/__tests__` and in the frozen components, then apply the change on a scratch copy and run those test files. Each collision is granted in the task or the item is changed; A never meets it first. A repo-scan test (it greps the whole tree) cannot be shown red on the start copy; write its red-proof as a named mutant, and keep "red on start copy" for fixture rows only (C-R203 T-RUN note, 1×). Evidence: C-R127-01 (glossary "Close" vs the frozen Modal ✕, `a-round-127.md` §3), C-R178-BADGE-SELECTOR (W2 mandatory while its selector tests were protected, `a-round-178.md` DEVIATION 2). **When B cannot pre-apply the change** (a behaviour not yet written): the task carries the exact grep (regex and root folders, never a hand-picked file list), its hit list and one class ruling R for that pattern; A re-runs the same grep and applies R only to its hits, reporting each hunk old → new; a hit R does not fit is a STOP. Evidence: C-R209-01 (B grepped 15 chosen files, `b-round-208.md` l.36; the 10th hit was elsewhere) (1×). **Deleted or renamed export:** grep its importers in `app/**` and run `npm run typecheck` on the scratch copy as well as vitest; an identity assertion on a deleted export passes vitest as `undefined === undefined` and fails only in tsc. Evidence: B-R228-VACUOUS-DELETED-EXPORT (`tempo.test.ts` T10, round-229 pre-check) (1×).
24. **Same pre-existing clause in every measurement row.** If one row says "listed with its ref result" for a failure that is identical in ref, every sibling measurement row (contrast, visibility, boxes) says the same or names the element as its target. Evidence: C-R202-02 failed CONTRAST on a ref-identical button while RING-VISIBLE listed the same class (1×).
29. **Render condition of every named signal.** Each `data-*` attribute, selector or element a task names as a liveness or acceptance signal gets a source grep that shows which branch renders it, and the task's state must satisfy that branch. Evidence: A-R214-DEV-RANGE-LIVE (`[data-range-end]` renders only for all-tracks ranges, `ArrangementLane.tsx` l.1016) (1×). **A state recipe is a signal too:** every step a task gives to reach a state ("clear the selection with …") was run once by B in the browser at the baseline; Escape does not clear a time selection in this Studio (an empty-lane click does). Evidence: C-N229-S3-METHOD (1×).
30. **A named tool must process the named paths.** Before an acceptance cites a command on a path (lint, format, scan), B checks that the repo config does not ignore that path. Today `npx biome check perf/` checks nothing (`biome.json` includes `app/**` only): cite `npm run typecheck` for `perf/**` until root/Saba change the config. Evidence: GATE206-S2, C-R214-BIOME-PERF-VACUOUS (rounds 206, 208, 214).
31. **Timeout headroom before adding rows.** For every test file the task adds rows to, B reads the last gate `verify.log` and A's last covering-run numbers; a test above 50 % of its declared timeout (`{ timeout }` on the test or describe, else the vitest default) is split or ruled before more rows land. Evidence: GATE212-B1 (CP12 25.4 s at gate 211, 33.3 s at gate 212, 30 s limit), B-R212-TIMEOUT-HEADROOM (1×).
34. **Grant the whole contract section of a doc.** When a harness, budget or contract file changes, the task grants the doc's whole section that describes it (not named lines) and C's DOC row checks that section against the live file. Evidence: C-R208-01, C-R210-01, C-R209-02 DOC half (doc 163, 3×).
35. **Deps or lock change → notices grant.** Every task that files `root-deps-request.json`, or that follows any `package-lock.json` change (add, remove, `npm update`, transitive bump), grants `THIRD_PARTY_NOTICES.md` and `third-party-licenses.test.ts`, and lists TL4 (version anchors) and TL5 (notices sync) as covering tests. File a remove request only after the code no longer imports the package (C source grep = 0): root installs before the round. Evidence: D-29z226, D-29z228/D-29z229 (rounds 219–220) (rule, 0× failures yet).
36. **"Backend-blocked" is a claim to test, not a default.** Before a row on a purchased or signed-in page is written as BLOCKED, B tries the client path with Playwright `page.route` stubs (harness rule HR-LEGACY-STUBBED). If it runs, the row becomes `…-STUBBED-N`: it proves the client path only. The task keeps an unstubbed auth-guard row and a backend-only ownership row. Evidence: LEGACY-UI-220 sat BLOCKED; the stubbed probe at round-221 planning ran the real dialog and found B-R220-LEGACY-EXPORT-NO-STEMS (Medium, pre-existing since January) (1×).
37. **Event counts inside a time window are wallclock until a loaded run says otherwise.** Before a task makes a count of commits, frames or events bounded by timestamps (`t > firstMove`, `t < up`) a deterministic row, B checks a loaded or throttled replicate (6× or a concurrent-load run) and states the boundary rule; whole-interval counts and render-work sums are the exact candidates. Evidence: C-R224-01 (`interact.drag.fade.playing.commits-per-move` 60/59/60 under load, `componentsSum` 5782 ×3), a B contract-design gap in round 224 (1×).
39. **Persistent screen text is a budgeted row.** A task that adds anything permanently visible (helper text, label, badge, strip, a key appended to an existing line) names the quieter homes it rejected (tooltip, `?` sheet, empty-state-only, first-run-only, status) and carries a C row counting persistent text lines outside the timeline at 1440×900 and 1280×720, before and after. Evidence: SABA-B-8 (round-9 shortcut line grew to 19 keys by round 80; 13 helper sentences on the empty demo; no round looked at the whole screen) (1×).
41. **Perceptual axes follow the reference curve.** A control, envelope or readout that maps gain, volume or zoom onto pixels or time cites the reference's curve (Live: the dB fader taper) with a manual section before dispatch, and C measures three interior points (25/50/75 %) against it, not only the ends. Evidence: SABA-B-7 (clip envelope linear in gain since rounds 82–83; one bottom point is silent only for an instant) (1×).
42. **A Saba approval becomes a backlog id in the same planning.** When a policy section or user-review file with an approved request first reaches B, B adds its id to `backlog.json` (queue entry or `open_findings`) and to `feature-status.md` in that planning, with its place in the order; C's RT/AN rows grep the id. Evidence: SABA-B-7 (approved 2026-10-28, missing from both files until round-230 planning) (1×).

## Before handing over (A self-check)
(Also L38 under C: perf runs alone.)
11. **Report a STOP and change nothing else.** Write "STOP — needs B ruling on <criterion/id>" at the top of `a-round-N.md`, with the measurement, and leave the tree at the last consistent state. Evidence: rounds 142–143, 192.
12. **No styling-class selectors in tests.** Find elements by role, accessible name, text or `data-testid`. Before removing or renaming a class token, `grep -rn "<token>" app/**/__tests__` and fix every hit in a file you own; a hit in a protected or frozen file is a STOP (L11) with the hit list, not an edit. Do not assert a cascade from class tokens in jsdom; computed style (inheritance, unlayered rules) needs a browser. Evidence: C-R158-01, C-R154-01 (jsdom cascade); C-R178-BADGE-SELECTOR (the code-reviewer found the hits in protected tests; A reproduced them, reported a BLOCKER and did not edit).
13. **Guards parse whole tags.** A source scanner that checks a class "near" a tag must parse the whole JSX element (tag to `>`), not a fixed line window. Prove it with one mutant that would false-pass. Evidence: C-R194-02.
14. **Unique accessible names in any dialog you touch.** In the covering tests (the speed-rule set: test files that cover the changed code; the full suite stays a gate row), `getAllByRole(role, {name})` returns 1 for every button name in the dialog. Evidence: C-R127-01 (1×; A found it through the granted tests and stopped, the cause was the task, see L23).
15. **Measure contrast you introduced.** For a colour/token change, measure each touched boundary, including same-token overlaps (brass line on a brass bar) and ring vs the neighbouring border, before handover; put the ratios in the report. Evidence: B-R193-UNMEASURED-INFO, C-R193-02, C-R149-2, C-R196-01.
26. **Docs cite only tests that exist.** Every test behaviour the implementation doc claims has a named row in the test file (grep the row id), or the claim is removed; C's AN-REVIEW row checks it. Evidence: GATE204-B1 (gate 204 blocked on doc 161 l.111) (1×). Its `## ` headings contain, as an in-order subsequence, the seven `## ` headings of `docs/implementation/TEMPLATE.md` after its `## Prompt` section (`## კონტექსტი` … `## TODO / შემდეგი ნაბიჯები`; compare `grep -n '^## '` on both, skipping TEMPLATE's `## Prompt` line); extra headings are allowed. Evidence: C-R216-01 (doc 169 had no `## არქიტექტურა`) (1×); C-R230-01 (the round-230 wording also required `## Prompt`, which 0 of 178 docs have).
28. **The implementation doc status line is final when A writes it.** A writes l.4 as exactly `Completed (C round N PASS)` (N = this round; for a stage of a longer feature `In Progress (stage k of n; C round N PASS)`), with no hash, gate round or "pending". It is the post-PASS value, true only at HEAD; in the working tree it is a claim pending C, and `c-round-N.json` stays the source of truth. Nothing reaches HEAD without C PASS (the gate skips C FAILs). On a re-dispatch as round N+1, that doc's l.4 is granted implicitly, for rewriting N only. C checks the string byte for byte. Root no longer amends it. Root request for a gate-side substitution (`b-round-215-root-request-l28.md`, D-29z214): L28 switches only after root confirms it. Evidence: 8 stale-status findings in rounds 200–214 under the old rule (`b-round-214/l28-status.txt`), ROOT-L28-AMEND-MISSED, GATE214-DOC168-STATUS. **Multi-stage feature:** the task of the final stage also grants l.4 of every earlier-stage doc of that feature, each to `Completed (C round M PASS)` with M = the C round that passed the final stage; B's planning runs `grep -rn 'In Progress (stage' docs/implementation` and ties every hit to a granted line or an open backlog stage. Evidence: B-R229-DOC170-STATUS (doc 170 kept `In Progress (stage 1 of 2; C round 218 PASS)` after stage 2 passed in C round 221) (1×).
27. **Mocked-hook rerender needs a fresh element.** When a test flips a mocked hook's state (`useAuth`, `useLeadMagnet`) and calls `rerender`, pass a newly created element (`rerender(ui())`); the same element reference bails out and the hook is never re-read. Evidence: B round-205 planning HF6b sketch (1×).
32. **A failing or slow covering test is a STOP, even if pre-existing.** The gate runs the full suite, so a covering-run failure (a timeout included) is written at the top of `a-round-N.md` as "STOP — needs B ruling" (L11), not under "For B/root"; a test above 50 % of its timeout is listed at the top with its time and limit; when a gate `verify.log` exists for that test, report both A's time and the last gate time, and the higher one decides (A feedback, round 215). Evidence: round 212, A found CP12 failing its 30 s timeout (31.8 / 32.8 s), called it pre-existing and listed it as a root risk (`a-round-212.md` l.38–41); C passed, gate 212 failed (GATE212-B1) (1×).
33. **A regression this round causes is a STOP, not a note.** If your change (or your reviewer) shows a Medium+ regression whose fix is outside the grants, write STOP (L11) instead of handing over with a ruling request. Evidence: C-R202-01 (A reported A-R202-REVIEW-INPUT-ERROR-BORDER in `a-round-202.md` §6 and handed over; C failed the round) (1×).
40. **Changed a `data-testid` element? Its tests join the covering set.** Any change to an element that carries a `data-testid` (classes, wrapper, structure, a deviation from B's plan included) → grep that testid in `app/**/__tests__` and run every hit file; a hit that pins classes in a frozen file is a STOP (L11) with the hit list. B's L23 pre-check covers B's sketch, not A's later restructuring. Evidence: GATE226-B1 (track-layout pinned `basis-full` on the footer slots; gate 226 failed) (1×).

## What to probe first (C)
16. **Longest text state first.** For copy/font rounds, open the state with the longest text (Playing, errors, multi-select, 1280 width) before the rest. Evidence: C-R142-01, C-R145-01, C-R146-01.
17. **Every consumer of a changed token.** Grep the changed token, then measure fields, borders and popups that the task did not list (e.g. GuestForm on /support). Evidence: C-R194-01.
18. **Fresh first visit, not only the preset.** Measure CLS/focus on a fresh profile with empty storage as well as the "seen" state. Evidence: C-R189-01 (1×).
19. **Focus under sticky chrome and in clipped boxes.** For focus work, Tab through the rows that scroll under sticky strips and the cards inside `overflow` containers, at 1280×720. Evidence: C-R196-02, C-R196-03, C-R198-01/02.
20. **Glyph coverage.** For a font change, list the non-ASCII glyphs on screen and check the platform font for each (CDP `getPlatformFontsForNode`). Evidence: C-R151-3, C-R154-02.
21. **Inherited weight on new spans.** Check computed `font-weight` and platform font of every span a font change adds. Evidence: C-R154-01 (1×).
22. **A stopped with no diff → short round.** If `a-round-N.md` reports a STOP and `git status` shows no change, run SOURCE-SCOPE and the auth guard only, report FAIL "not implemented" in one table, and do not re-run feature rows. Evidence: round 192 (C $3.22 on a no-op).
25. **Playwright file chooser.** Register `page.on('filechooser')` first and wait about 500 ms before the action; `Promise.all([waitForEvent('filechooser'), action])` misses at random. Evidence: C round 202 (A's Space miss; 11/12 ref misses, then 36/36 + 24/24) (1×).
38. **Perf runs alone (A and C).** Never run vitest, tsc, builds or another browser job while a Playwright perf spec runs; an overlapped attempt is environment-invalid, is kept as evidence, and uses one of the 2 replacement attempts. Evidence: C-R224-01 run-1 (C's own jobs overlapped PERF-1b-i) (1×).
