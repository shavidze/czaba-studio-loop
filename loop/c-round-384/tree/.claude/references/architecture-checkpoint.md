# არქიტექტურული checkpoint — საერთო contract

მიზანი: სტრუქტურული რისკი დროულად გამოჩნდეს, მაგრამ ყოველი მცირე რაუნდი აუდიტად არ იქცეს. ფაილის სიგრძე თავისთავად არც სიგნალია და არც ბაგი; ხაზების ზღვარი, სავალდებულო refactor ან ფრაგმენტაცია არ არსებობს.

## რისკის სიგნალები (მხოლოდ ფაილი/ხაზის მტკიცებულებით)
1. შერეული პასუხისმგებლობა — owner იღებს დამოუკიდებლად შემოწმებად ქვესისტემას, რომელიც მის როლს არ ეკუთვნის.
2. მფლობელობის/coupling-ის ცვლილება — state, ref ან ქცევა გადადის context-ს, component-სა და `lib/`-ს შორის, ან ჩნდება ორმხრივი დამოკიდებულება.
3. განმეორებითი ძვირი ცვლილება — ერთ რეგიონს რამდენიმე რაუნდი ცვლის და ყოველ ჯერზე ფართო კონტექსტი, mock ან რეგრესია სჭირდება.
4. დაკავშირებული state/lifecycle — არსებულ owner-ს ემატება state, effect, timer, listener ან cleanup სხვა lifecycle-ისთვის.

## როლები
- Reviewer (`code-reviewer`): diff-ში სიგნალზე წერს Architecture note-ს; აუდიტს არ აცხადებს.
- Implementer (A): note-ს ანგარიშში გადასცემს; ownership-ის გარეთ არაფერს გამოყოფს.
- Planner (B — სამუშაო ციკლის დავალების ავტორი): note-ს backlog-ში ერთხაზიან სიგნალად ინახავს, წყვეტს checkpoint-ის საჭიროებას, extraction-ს მხოლოდ ცალკე დავალებად გეგმავს.
- Checkpoint reviewer (`frontend-architect`, read-only): checkpoint-ს ატარებს planner-ის ან root-ის მოთხოვნით.
- root / მომხმარებელი: ამტკიცებს scope-ს და რიგს.

## როდის
- feature-ის ან ეტაპის დასრულებისას, სრული რეგრესიის მომენტში;
- როცა ერთ owner-ზე სიგნალები რამდენიმე რაუნდში გროვდება;
- planner-ის ან root-ის მოთხოვნით.
ყოველ რაუნდში არა; მოცულობა — მხოლოდ შეხებული ქვესისტემა.

## შედეგი
1. შემოწმებული commit, დაუკომიტებელი path-ები, drift;
2. ვერდიქტი: ზიანს აყენებს თუ არა ახლა, მტკიცებულებით (ცვლილების ღირებულება, ტესტის სირთულე, ბაგის კლასი, rendering);
3. keep vs extract თითო სიგნალზე: cohesion/ერთი lifecycle/ნაკლები prop plumbing თუ გამოყოფის სარგებელი; ღირებულება low/medium/high და რისკი;
4. მაქსიმუმ 3 პრიორიტეტული ცვლილება და რა რჩება უცვლელი, რატომ;
5. ერთი შეზღუდული დავალების წინადადება: ownership, მიღების კრიტერიუმები, ფოკუსირებული ტესტები. ეს წინადადებაა, არა დამტკიცებული scope.
„Refactor ახლა არ ღირს“ სრულფასოვანი შედეგია. სრული გადაწერა, generic hook-ებად დაშლა, ერთჯერადი abstraction — არა.

## უცვლელი წესები
- აუდიოს timing, refs, gesture lifecycle, Undo/Redo-ს ატომურობა, საჯარო hook-ის (მაგ. `useArrangement()`) ფორმა და არსებული ტესტები ქცევით უცვლელი რჩება და ტესტით მოწმდება.
- Auth, შეძენილ მასალაზე წვდომა და დაცული ფაილები არ იცვლება.
- Architecture note მიმდინარე რაუნდში გამოსასწორებელი finding არ არის. გაყინულ scope-ზე ის გადაეცემა planner-ს, root-ს ან მომხმარებელს.
- Planner წინადადებას ინახავს და backlog-ში დავალებად ავტომატურად არ ჩასვამს; მიმდინარე scope-ის ფუნქციებთან რიგს root ან მომხმარებელი წყვეტს.

## Integrity vs შესრულება
`npm run agents:check` ამოწმებს reference-ების არსებობას და `.codex` mirror-ების დამთხვევას; ის არ ადასტურებს, რომ review ან checkpoint ჩატარდა. შესრულების მტკიცებულებაა მხოლოდ ანგარიში შემოწმებული commit-ით და ციტირებული შედეგით.
