Root measures these in Ableton Live 12 on Saba's computer when it is online, and writes the result to `reference/ableton-live-measurements-<date>.md`. That file outranks forum posts and inference. A result that differs from an agreed CZABA behaviour goes to Saba as a question; it never silently changes the agreed behaviour.

## LIVE-MEAS-11C-OFFSET (B, 2026-10-30, round 271 planning; SABA-B-11c stage 2, SABA-Q-11C-NUDGE, SABA-Q-11C-REALIGN)
**Why:** Saba chose relative snap, option (a). The Live 12 manual (6.7, 6.9, 6.10) is silent about clips that sit off the grid. On 2026-10-30 root could not measure (a Windows overlay blocked input).

**Setup:**
- a new Live Set at 120 BPM, Arrangement View;
- one audio clip on track 1;
- grid fixed at 1 Bar (right-click → Fixed Grid → 1 Bar), Snap to Grid on (Ctrl+4 so the grid is on).

**Steps (read the clip's Start in Clip View, or the status bar, after each):**
1. Alt-drag the clip so its start is at about 2.1.2 (off the grid, inside bar 2). Write down the exact start.
2. Plain drag right by about 1 bar and release. Where does the start land: 3.1.1 (absolute) or 3.1.2 (relative)?
3. A small jitter: press on the clip, move about 3–5 px, release. Does the start change?
4. Drag left past the song start. Does it stop at 1.1.1 or at 1.1.2?
5. With the clip selected, press → once, then ← once. Where does the start land each time?
6. Repeat step 2 with a second clip selected at an on-grid start (a group drag). Do both move by exactly 1 bar?
7. Trim the left edge of the off-grid clip with a drag. Does the edge land on a bar line?

**What to write:** the Live version, OS, grid setting, and the start after each step; one screenshot per step where possible. Keep confirmed observations separate from inferences.
