## Findings for B
1. **C-R198-01 (Low, pre-existing, `deferred_low_polish`).** A keyboard step on a range slider that the chrome partly covers does not reveal it.
   - **Steps:**
     1. `/studio-lab` at 1280×720, rich scene.
     2. Set the timeline scroller's `scrollTop` to 32, so "Volume — Original video sound" is cut by 6 px (top 307 < chrome bottom 313).
     3. Mouse-click the slider's visible part.
     4. Press ArrowUp.
   - **Expected (task row POINTER):** the ring shows and the control is revealed.
   - **Actual:** the value changes and the ring shows (`solid`, keyboard source), but `scrollTop` stays 32 and the top stays 307, so the slider is still 6 px under the chrome. Tree = ref. R91 cannot see it because no focus event fires on an element that is already focused, and a range input's ArrowUp does not scroll.
   - **B rules on this:** POINTER-198 passed on the specified button controls (Video fold, Video Mute). The range-slider variant does not meet the row's "reveals the control" text. B decides whether the pre-written clause "keyboard stop above the chrome bottom → Medium" applies here. C reads that clause as aimed at Tab stops.
   - **Why Low:** the control is only partly covered (WCAG 2.4.11 minimum, "not entirely hidden", is met), and the case needs a mouse press first.
   - **Evidence:** `out/chrome/tree-1280/result.json` step `cut-video-volume-ArrowUp`, and the same step in `out/chrome/ref-1280/result.json`.
2. **C-R198-02 (Low, pre-existing, `deferred_low_polish`).** At 1280 the bottom ring side of the Video-row Mute and Solo is clipped.
   - **Measurements:** 0 changed px in the rich scene after the reveal, and 18 in the default scene, against 80 on the other sides and on the Music, Stems and SFX rows. Default 1280 is tree = ref (18), and round 197 recorded the same 18.
