# Scene Builder-ის კატალოგის ჩატვირთვა

**თარიღი:** 2026-10-03
**სტატუსი:** Completed
**შეცვლილი პროექტი:** Store

## კონტექსტი

AudioContext-ის closePlayer ყოველი render-ისას ახალი ფუნქციაა. Scene route-ის ჩატვირთვის effect ამ ფუნქციაზე იყო დამოკიდებული და თვითონვე იძახებდა მას. შედეგად context-ის განახლება ხელახლა იწყებდა კატალოგის მოთხოვნას, სამუშაო სივრცე იტვირთებოდა უწყვეტად და API აბრუნებდა 429-ს.

## მიდგომა

უახლესი closePlayer ინახება ref-ში. კატალოგის მოთხოვნა დამოკიდებულია მხოლოდ productId-ზე, მომხმარებლის ID-სა და ხელით Retry-ზე. Token-ის განახლება აახლებს API-ის token-ს, მაგრამ არ ასუფთავებს სცენას და არ იწყებს კატალოგის ხელახალ ჩატვირთვას.

429 აჩერებს მოთხოვნას და Retry 15 წამით ითიშება. ავტომატური განმეორება არ ხდება. არსებული API client-ის timeout რჩება მოქმედი.

## შეცვლილი ფაილები

- `app/routes/scenes.$productId.tsx` — სტაბილური ჩატვირთვა და loading/error სამუშაო სივრცე.
- `app/lib/__tests__/sfx-scene-route.test.tsx` — context render-ისა და token refresh-ის რეგრესიები.

## პრობლემები და გადაწყვეტები

მრავალი მოთხოვნა → ჩატვირთვის effect აღარ არის დამოკიდებული AudioContext-ის ცვალებად callback-ზე. ჩატვირთვისა და შეცდომის განსხვავებული სიმაღლე → ორივე იყენებს იმავე preview/inspector ჩარჩოს. Motion მოქმედებს მხოლოდ waveform-ის opacity/scale-ზე; reduced motion სტატიკურ გამოსახულებას აჩვენებს.

## ტესტირება

სამი ტესტი ადასტურებს ერთ მოთხოვნას ცვალებადი callback-ისა და token-ის განახლების დროს, შეცდომის შემდეგ მხოლოდ ხელით განმეორებას და 429-ის დროს backoff-ს.
