# Explain Code

კოდის ახსნა middle developer-ისთვის - ვიზუალური დიაგრამებით, ნაბიჯ-ნაბიჯ walkthrough-ით და "ხაფანგების" გამოყოფით.

## ახსნის სტრუქტურა

### 1. მოკლე მიმოხილვა

ერთ-ორ წინადადებაში - რას აკეთებს ეს კოდი და რატომ არსებობს?

### 2. დიაგრამა (ASCII Art)

**ყოველთვის დახატე** კოდის flow, სტრუქტურა ან კომპონენტებს შორის კავშირი.

#### Flow დიაგრამა
```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Input     │────►│  Process    │────►│   Output    │
│  (Props)    │     │  (Logic)    │     │  (Result)   │
└─────────────┘     └─────────────┘     └─────────────┘
```

#### Component Tree
```
App
├── Header
│   ├── Logo
│   └── Navigation
├── Main
│   ├── Sidebar
│   └── Content
└── Footer
```

#### State Machine
```
         ┌──────────┐
         │  IDLE    │
         └────┬─────┘
              │ play()
              ▼
         ┌──────────┐
    ┌───►│ PLAYING  │◄────┐
    │    └────┬─────┘     │
    │         │ pause()   │ resume()
    │         ▼           │
    │    ┌──────────┐     │
    │    │ PAUSED   │─────┘
    │    └────┬─────┘
    │         │ stop()
    │         ▼
    │    ┌──────────┐
    └────│ STOPPED  │
         └──────────┘
```

### 3. ნაბიჯ-ნაბიჯ Walkthrough

ეტაპობრივად ახსენი რა ხდება, როგორც კოდი სრულდება:

**ახსნის ფორმატი:**

> **ნაბიჯი 1 - Mount:** როცა კომპონენტი პირველად გამოჩნდება DOM-ში...
>
> **ნაბიჯი 2 - Fetch:** useEffect-ის callback გაეშვება და...
>
> **ნაბიჯი 3 - Transform:** როცა data დაბრუნდება, useMemo...

### 4. ხაფანგები (Gotchas)

**გამოყავი ის ნიუანსები** სადაც დეველოპერები ხშირად უშვებენ შეცდომას:

```
⚠️ ხაფანგი #1: Stale Closure
────────────────────────────
პრობლემა: useEffect-ში count ყოველთვის 0-ია
მიზეზი: closure "იმახსოვრებს" საწყის მნიშვნელობას
გამოსწორება: დაამატე count dependency-ში

⚠️ ხაფანგი #2: Memory Leak
────────────────────────────
პრობლემა: კომპონენტის unmount-ის შემდეგ setState ცდილობს update-ს
მიზეზი: async operation არ გაუქმდა
გამოსწორება: cleanup ფუნქცია useEffect-ში
```

## ანალოგიები რთული კონცეფციებისთვის

### Closure
```
წარმოიდგინე როგორც "სნეპშოტი" - ფუნქცია იმახსოვრებს
გარემოს სადაც შეიქმნა, როგორც ფოტო იმახსოვრებს მომენტს.
```

### Event Loop
```
წარმოიდგინე როგორც რესტორნის მიმტანი:
1. მიდის თანმიმდევრობით თითოეულ მაგიდასთან (sync code)
2. თუ კერძი მზადდება სამზარეულოში, არ დგას და ელოდება
3. აგრძელებს სხვა მაგიდებს
4. როცა კერძი მზადაა, მიაქვს შესაბამის მაგიდაზე (callback)
```

### Virtual DOM
```
წარმოიდგინე როგორც Word დოკუმენტის შედარება:
- ჯერ გამოითვლება რა შეიცვალა (diff)
- შემდეგ მხოლოდ ის ნაწილი იბეჭდება თავიდან (patch)
- არა მთელი დოკუმენტი
```

### useMemo / useCallback
```
წარმოიდგინე როგორც "შენიშვნები კალკულატორზე":
- პირველად ითვლი და იწერ შედეგს
- შემდეგ ჯერზე უყურებ შენიშვნას, არ ითვლი თავიდან
- თუ საწყისი რიცხვები შეიცვალა, მხოლოდ მაშინ ითვლი ახლიდან
```

## საუბრის ტონი

- **მეგობრული და სასაუბრო** - არა ლექცია, არამედ კოლეგასთან საუბარი
- **"შენ" მიმართვა** - "როცა შენ გამოიძახებ ამ ფუნქციას..."
- **აღიარე სირთულე** - "ეს ცოტა tricky-ა, მოდი ნაბიჯ-ნაბიჯ"
