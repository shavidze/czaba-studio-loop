# Studio Video Sync

**თარიღი:** 2026-10-03
**სტატუსი:** Completed
**შეცვლილი პროექტი:** Store და Backend

## კონტექსტი

Scene Builder-ის ხმები უნდა დაემთხვეს მომხმარებლის ვიდეოს კადრებს. ვიდეო რჩება მოწყობილობაზე, ხოლო ანგარიშზე ინახება სცენის ხმები, ვიდეოს აღწერითი metadata, ნიშნულები და გამეორების საზღვრები.

## მიდგომა

მომხმარებელი ირჩევს ადგილობრივ ვიდეოს. Browser კითხულობს ხანგრძლივობასა და გამოსახულების ზომას; ფაილი გამოიყენება object URL-ით და ქსელში არ იგზავნება. ვიდეოს ხანგრძლივობა ხდება სცენისა და WAV-ის ხანგრძლივობა. მხარდაჭერილია browser-ის ვიდეო ფორმატები და არსებული 300-წამიანი ზღვარი.

ერთიანი Play/Pause და seek მართავს ვიდეოსა და უკვე დამუშავებულ PCM-ს. აუდიო იწყება ვიდეოს decoded seek-ისა და play promise-ის დასრულების შემდეგ, რეალური ვიდეოდროიდან. გადახვევის ან drift-ის შესწორება აჩერებს ორივეს და სინქრონულად თავიდან იწყებს. Buffering ან შეცდომა აჩერებს საერთო დაკვრას. გამეორების დროს Pause ინარჩუნებს მონაკვეთის შიგნით სწორ დროს.

Browser-ის requestVideoFrameCallback განსაზღვრავს ნაჩვენები კადრის timestamp-ს, რომელიც გამოიყენება Place at current frame-ისა და სახელდებული მომენტებისთვის. მხარდაჭერის გარეშე მოქმედებს ზუსტი დროის არჩევა.

ვიდეოს ხმა ნაგულისხმევად დადუმებულია. მისი დონე და Mute გამოიყენება preview-ში; WAV შეიცავს Scene Builder-ის ხმებს. ინტერფეისი ამას პირდაპირ ამბობს. ვიდეოს მონტაჟი და ვიდეოფაილის ექსპორტი არ დამატებულა.

## არქიტექტურა

არსებულ version 1 scene JSON-ს ემატება optional Video metadata. ძველი სცენები თავსებადია. Backend ამოწმებს duration-ის დამთხვევას, filename-ის ფორმას, dimensions-ს, volume-ს, მაქსიმუმ 100 უნიკალურ ნიშნულს და loop-ის საზღვრებს. ახალი DB მიგრაცია ამ ცვლილებისთვის საჭირო არ არის.

სცენის გახსნისას ვიდეო თავიდან ასარჩევია. ხმების პოზიციები, ნიშნულები და repeat პარამეტრები რჩება. ვიდეოს შეცვლისას განსხვავებული ხანგრძლივობა უარყოფილია; სცენის ხმები არ იჭრება ჩუმად.

## შეცვლილი ფაილები

- `SfxSceneBuilder.tsx` — ადგილობრივი ვიდეო, საერთო transport, კადრზე მოთავსება.
- `SfxVideoSync.tsx` — მშვიდი preview და ფიქსირებული ზომის inspector, Motion და keyboard navigation.
- `sfx-scene.ts` — optional ვიდეოს metadata-ს parsing/validation.
- `sfx-video.client.ts` — decoded seek, cancellation და გამეორების პოზიცია.
- Scene/Video ტესტები — ზუსტი ექსპორტი და transport-ის რეგრესიები.
- Backend Scene DTO/service/tests — ანგარიშზე metadata-ს შენახვა და ვალიდაცია.

## პრობლემები და გადაწყვეტები

გამეორების შემდეგ Pause სცენის ბოლოს გადადიოდა → გამოიყენება საერთო wrapped პოზიცია. ვიდეოს play rejection-ისას აუდიოს მარტო გაგრძელების რისკი → SourceNode იქმნება მხოლოდ წარმატებული ვიდეოდაკვრის შემდეგ. ვიდეოს ხელახლა არჩევისას layout-ის ცვლილება → aspect-video და ფიქსირებული inspector; Motion არ ცვლის სიმაღლეს.

## ტესტირება

ავტომატური ტესტები ამოწმებს 30-წამიან WAV-ს სამ კონკრეტულ პოზიციაზე, საწყის/ბოლო სიჩუმესა და მოსასმენ PCM-თან ყველა ნიმუშის დამთხვევას. Metadata გადის შენახვა/გახსნის roundtrip-ს. Transport ტესტავს გამეორებულ Pause-ს, decoded frame-ის მოლოდინს, cancellation/timeout-ს, play rejection-სა და რეალურ ვიდეოდროზე აუდიოს დაწყებას.

ბრაუზერის სატესტო account API-ით გაიარა ადგილობრივი 30-წამიანი MP4, სამი ხმა 5/12/25 წამზე, ნიშნული, repeat, Save/Open, ხელახლა არჩევა და 30-წამიანი stereo 96 kHz WAV. 390px viewport-ში horizontal overflow არ არის. ანგარიშის რეალურ backend service-ზე ცალკე ტესტები ამოწმებს metadata-ს roundtrip-სა და წვდომას.

ადგილობრივ CzabaDb-ში Scene Builder-ის არსებული 017 მიგრაცია შესრულდა ორჯერ იდემპოტენტობის შესამოწმებლად. Azure SQL-ის czaba-test ბაზაში 017 მიგრაცია წარმატებით შესრულდა; PK_SfxScene და IX_SfxScene_UserId_ProductId_UpdatedAt დადასტურდა.
