# My Account

## დავალება: მომხმარებლის ანგარიშის მართვის გვერდი ("My Account")

## User Story:

**As a** რეგისტრირებული მომხმარებელი,
**I want to** მქონდეს "My Account" გვერდი ჩემს პირად კაბინეტში, სადაც შევძლებ ჩემი პროფილის სახელის განახლებას და უსაფრთხოების მიზნით, ჩემი ანგარიშის პაროლის შეცვლას,
**So that** მქონდეს კონტროლი ჩემს პერსონალურ ინფორმაციაზე და შევძლო ჩემი ანგარიშის დაცულობის უზრუნველყოფა.

---

## ტექნიკური მოთხოვნები:

### 1. დაცული მარშრუტი:

- დარწმუნდი, რომ `/account` მარშრუტი დაცულია და ხელმისაწვდომია მხოლოდ ავტორიზებული მომხმარებლებისთვის.

---

### 2. გვერდის სტრუქტურა:

- გვერდი უნდა შედგებოდეს ორი ძირითადი სექციისგან: "პროფილის ინფორმაცია" და "პაროლის შეცვლა".

- **იმეილის ველი:** აჩვენე მომხმარებლის მიმდინარე იმეილი, მაგრამ გახადე ის **არა-რედაქტირებადი (disabled/read-only)**.

---

### 3. პროფილის ინფორმაციის რედაქტირება:

- **UI:** უნდა არსებობდეს ველი მომხმარებლის სახელის (displayName) შესაყვანად.

- **მონაცემების ჩატვირთვა:** გვერდის ჩატვირთვისას, ეს ველი უნდა შეივსოს მომხმარებლის მიმდინარე სახელით.

- **განახლების ლოგიკა:** "შენახვა" ღილაკზე დაჭერისას:
    - გამოიძახე Backend API-ს profile update endpoint.
    - აჩვენე წარმატების შეტყობინება (Toast Notification).

---

### 4. პაროლის შეცვლა:

- **UI:** უნდა არსებობდეს სამი ველი: "მიმდინარე პაროლი", "ახალი პაროლი" და "გაიმეორეთ ახალი პაროლი".

- **ლოგიკა:** "პაროლის შეცვლა" ღილაკზე დაჭერისას:

    - **ვალიდაცია:** შეამოწმე, რომ "ახალი პაროლი" და "გაიმეორეთ ახალი პაროლი" ველები ემთხვევა.

    - **რე-ავტორიზაცია:** უსაფრთხოებისთვის, ჯერ გამოიძახე რე-ავტორიზაციის endpoint, რათა მომხმარებელმა ხელახლა დაადასტუროს თავისი იდენტობა "მიმდინარე პაროლის" შეყვანით.

    - **პაროლის განახლება:** რე-ავტორიზაციის წარმატებით გავლის შემდეგ, გამოიძახე პაროლის განახლების endpoint ახალი პაროლის დასაყენებლად.

    - წარმატების შემთხვევაში, გაასუფთავე ველები და აჩვენე წარმატების შეტყობინება.

    - დაამუშავე შეცდომები (მაგ., თუ მიმდინარე პაროლი არასწორია).
