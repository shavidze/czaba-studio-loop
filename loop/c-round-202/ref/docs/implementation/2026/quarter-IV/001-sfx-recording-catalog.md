# SFX ჩანაწერების მოსმენა

**თარიღი:** 2026-10-03
**სტატუსი:** Completed — ადგილობრივი იმპლემენტაცია; გამოქვეყნება დარჩენილია
**შეცვლილი პროექტი:** Store

## კონტექსტი

Premium SFX კოლექციის ჩანაწერები დამოუკიდებელი აუდიოა. მომხმარებელი არჩევს მისთვის გამოსადეგ ჩანაწერს; მუსიკის სინქრონული stems-ის მიქსერი ამისთვის საჭირო არ არის.

## მიდგომა

Claude-ის დაწყებული `feat/sfx-recording-catalog` გაგრძელდა იმავე ბრანჩზე. პროდუქტის გვერდიდან და Downloads-იდან მომხმარებელი ხსნის `/recordings/:productId` კატალოგს. თითო ჩანაწერს აქვს სახელი, რეალური ხანგრძლივობა, ორიგინალის ტექნიკური მონაცემები, Play/Pause და დროის არჩევა. აღწერა ჩანს მხოლოდ მაშინ, როცა შევსებულია.

ერთი HTMLAudioElement უკრავს მხოლოდ არჩეულ ჩანაწერს. გამოიყენება მოთხოვნისას მიღებული მოკლევადიანი URL და შეკუმშული მოსასმენი ასლი; სრული ZIP და ყველა ორიგინალი წინასწარ არ იტვირთება. მოსასმენი AAC ასლი არ ცვლის ნაყიდ ორიგინალებს.

## არქიტექტურა

Backend ამოწმებს პროდუქტის შეძენას და ჩანაწერის კუთვნილებას. Remix ქმნის კონკრეტული ფაილის 15-წუთიან token-ს. R2 Worker ამოწმებს token-ის დანიშნულებას, პროდუქტს, ფაილსა და ვადას. დაცულ პასუხებზე მოქმედებს `no-store`.

## შეცვლილი ფაილები

- `app/routes/recordings.$productId.tsx` — კატალოგი, loading/empty/error/access-denied მდგომარეობები და ავტორიზაციის განახლების შემდეგ ერთი განმეორებითი მოთხოვნა.
- `app/hooks/useRecordingPlayer.ts` — დაკვრა, გადართვა, დროის არჩევა, შეცდომა და cleanup.
- `app/components/recordings/RecordingCatalogRow.tsx` — ჩანაწერის ხელმისაწვდომი კონტროლები.
- `app/routes/api.recording-stream.ts`, `app/lib/r2-tokens.server.ts` — დაცული URL-ის მიღება.
- `app/services/api/client.ts` — კატალოგის ტიპები და API მეთოდი.
- პროდუქტის გვერდი და `account.downloads.tsx` — შესასვლელი ბმულები; მუსიკის Studio-ს გზა შენარჩუნებულია.
- `workers/r2-proxy.js`, `cloudflare/r2-worker.js` — recording დანიშნულება და დაცული მიწოდება.
- შესაბამისი hook/route/token/Worker ტესტები.

## პრობლემები და გადაწყვეტები

- ახალი მოთხოვნის გაუქმების შემდეგ წინა ფაილი შეიძლებოდა ჩართულიყო → ჩატვირთულ წყაროს თავისი recording ID აქვს; გადართვა ძველ წყაროს ათავისუფლებს.
- URL-ის მიღებამდე არჩეული დრო იკარგებოდა → მიმდინარე არჩეული პოზიცია ინახება და წყაროს დაყენებისას გამოიყენება.
- შეცდომის შემდეგ ახალი ჩანაწერი წინა ჩანაწერის პოზიციას იღებდა → თითო ახალი მოთხოვნა პოზიციას თავიდან აყენებს.
- საჯარო preview შეიძლებოდა პარალელურად დარჩენილიყო → ჩანაწერის გაშვებისას საჯარო პლეერი იხურება.
- სხვა პროდუქტზე ან სხვა მომხმარებელზე გადასვლა → კატალოგი თავიდან იქმნება, ძველი აუდიო ჩერდება.
- ქსელის მოთხოვნების გაჭედვა → stream მოთხოვნებს აქვს დროის ზღვარი და მოსახერხებელი შეცდომის შეტყობინება.
