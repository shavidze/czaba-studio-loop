## When writing a task (B)
1. **Inventory before grants.** If the task has a stop-on-inventory rule, B runs the same scan first: same line, multi-line `cn()`/arrays, constants defined on a later line, child icons. Test the scanner on one known-shape mutant, and cite the result in the task. For focus/visibility work, also scan for visually hidden focusables (`opacity-0`, `invisible`, `sr-only` on or around a tabbable element) and rule on each hit; confirm "is it rendered at all" with an import grep. A static scan misses runtime-hidden focusables (closed menus, scroll-reveal blocks): also run a browser Tab probe with ≥ 2 s settle at 375, 1280 and 1440 and list every stop at effective opacity 0. Probe backward entry too (End, then Shift+Tab), with keys ≥ 1.2 s apart (Lenis animates 1.2 s). Before blaming a scroll jump on smooth scroll, check for an auto-opening scroll-lock popup (LeadMagnet: 8 s after a 40 % scroll) and stub the suspect. Signed-in header UI is browser-testable with `localStorage.auth_user` without `accessToken` (no backend call); do not mark it BLOCKED-AUTH. Evidence: B-R192-PLANNING-GAP, B-R194-K0-SCAN-GAP, B-R200-HIDDEN-FOCUSABLE-GAP (rounds 192, 194, 201 lost); C-R202-04/05; B-R203-LEADMAGNET-AUTO-OPEN-FOCUS (1×).
2. **Token value change → consumer rows.** For every changed colour token, list each UI-boundary consumer (text, border, field, ring) as a measured contrast row, before dispatch. Evidence: C-R193-01/02, C-R194-01, B-R193-UNMEASURED-INFO. **C (alias L17):** re-grep the changed token and measure the fields, borders and popups the task did not list (e.g. GuestForm on /support). Evidence: C-R194-01.
3. **Text or font change → widest-state box rows.** For each changed string or font, add a row for its longest state (Playing, error, multi-select) at 1280×720 and 1440×900, with the old-language/old-font swap as the control. Evidence: C-R142-01, C-R143-01, C-R145-01, C-R151-2, C-R154-01; C-R254-01 (a "no more scroll than HEAD" bound written without measuring the HEAD container: when a task bounds a container's growth, B's pre-check measures that container at HEAD and on the sketch at both viewports and writes the measured bound).
4. **One element, one rule.** When two clauses can bind the same element (e.g. "panels ±1 px" and "own text may change"), the task says which wins. Evidence: C-R151-1 (spec conflict), C-R143-01. A collision row is worded "no assertion lost; equal or stronger replacements allowed", never "assertions unchanged" next to a §-rule that allows replacements. Evidence: A-R256 grant rows 5/6 (1×). **Same key path, two clauses:** when one clause changes a shared guard (a gesture arm, an early return) and another freezes a later branch the same key reaches, the task rules the combined path and B's pre-check probes it (gesture on and off). Evidence: C-R267-01 (gesture arm vs frozen Ctrl+Arrow branch, D-29z575) (1×). **Ruling line:** every element that two clauses bind gets one line in the task, "<element>: clause X wins over clause Y", which C greps before measuring. Evidence: C-R287-01 (`text-sm` label vs "card keeps its box"; FAIL, fix-up 288) (1×).
5. **Scope as semantic changes, not line counts.** Do not write "exactly N changed lines" unless Biome's lineWidth (100) was checked on the result. Evidence: STORE2A-BUTTON-REFLOW / C-R193-03 (1×).
6. **Carry parked rows explicitly.** When planning a regression round, copy every `scope_additions` entry of the due `regression_rounds` item into a named row, or mark it "carried" in the task. Evidence: REG-DUX5-PLAYHEAD-RESCAN missed in round 199.
7. **Close what a later round fixed.** When a fix-up closes a bug, grep `deferred_low_polish` and `open_findings` for the same root cause and close or update those ids in the same planning. Evidence: A-R147-REVIEW-L2-BADGE-CLASS-SELECTOR stayed open 21 rounds after round 179 fixed it.
8. **A deferred Low on a test selector is a time bomb.** A Low that pins styling classes or source text is scheduled before the visual stage that changes those classes. Evidence: A-R147-REVIEW-L2 (deferred round 147) → C-R178-BADGE-SELECTOR (Medium, round 178 FAIL).
9. **Engine rounding.** Sub-pixel widths (1.5 px rings) are written with the measured Chromium result, or as "≥ 1 px painted". Evidence: C-R196-04 (1×).
10. **Rule on every STOP before re-dispatch.** When A reports a STOP, or C reports "B has not ruled", the next task carries the explicit ruling (accepted delta or changed criterion, with the finding id) before anything is re-dispatched. Evidence: C-R142-01, C-R143-01 (no `b-round-143*` ruling existed).
23. **Mandatory change vs frozen or protected file: grant or rule before dispatch.** For every mandatory item, grep its removed or renamed tokens and its new labels in `app/**/__tests__` and in the frozen components, then apply the change on a scratch copy and run those test files. Each collision is granted in the task or the item is changed; A never meets it first. A repo-scan test (it greps the whole tree) cannot be shown red on the start copy; write its red-proof as a named mutant, and keep "red on start copy" for fixture rows only (C-R203 T-RUN note, 1×). Evidence: C-R127-01 (glossary "Close" vs the frozen Modal ✕, `a-round-127.md` §3), C-R178-BADGE-SELECTOR (W2 mandatory while its selector tests were protected, `a-round-178.md` DEVIATION 2). **When B cannot pre-apply the change** (a behaviour not yet written): the task carries the exact grep (regex and root folders, never a hand-picked file list), its hit list and one class ruling R for that pattern; A re-runs the same grep and applies R only to its hits, reporting each hunk old → new; a hit R does not fit is a STOP. Evidence: C-R209-01 (B grepped 15 chosen files, `b-round-208.md` l.36; the 10th hit was elsewhere) (1×). **Attribute or state-contract change** (e.g. native `disabled` → `aria-disabled`, a new title): the sweep regex covers every assertion form (`.attr`, `hasAttribute`, `getAttribute`, `toHaveProperty`, `toBeDisabled/Enabled`), the consumer filter keys on the elements' accessible names and test accessors, not on helper identifiers, and every old literal (title, label) is grepped in `app/**/__tests__` and `perf/**`; a wider earlier list is never narrowed without a per-file ruling. Evidence: GATE276-T1 (SW1 missed `hasAttribute('disabled')`/`toHaveProperty('disabled'`, filtered by `undoButton`-style ids, and dropped `navigation-strings-ui` that `b-round-229/sys5-disabled-grep.txt` listed; gate 276 failed) (1×). **Deleted or renamed export:** grep its importers in `app/**` and run `npm run typecheck` on the scratch copy as well as vitest; an identity assertion on a deleted export passes vitest as `undefined === undefined` and fails only in tsc. Evidence: B-R228-VACUOUS-DELETED-EXPORT (`tempo.test.ts` T10, round-229 pre-check) (1×). **Grep roots for a removed or renamed accessible name, title, label or testid:** `app/**/__tests__` **and** `perf/**` (and any e2e folder); `test:perf` is not a gate row, so a stale perf locator fails silently. Evidence: C-R258-01 (Pause label, round 256, and the clip-body title, rounds 252–253, broke PERF-1a/1b-i unnoticed for 33 rounds) (1×). **The scratch pre-check applies a sketch of every behaviour change, not only the copy items.** Evidence: RC-R252-PRECHECK-SCOPE (round 252's pre-check applied items 3–4 only; IM4's collision surfaced at A) (1×). **Moved element → grep the destination too:** when an element moves into a container, also grep `app/**/__tests__` for the testids and role names of that container's existing children (they pin child counts and sibling order), and run every hit file on the scratch copy. Evidence: gate 262 (`track-layout.test.tsx` l.867 pinned the footer row to 2 children; B grepped only Master tokens; C PASS, gate red) (1×). **Specified test rows run on the sketch too:** when the task fixes a new test row's assertion semantics (`toBe` vs `toEqual`, identity, timing), B writes those rows into the scratch and runs them against the sketch, not only the existing covering files; every identity or sample-by-sample comparison gets a named mutant that turns it red, run with the module graph the test really uses (a shared cached module makes both sides one object). Evidence: B-R282-DW-UNRUN / C-R282-01 (DW3/DW9 `toBe` on a rebuilt wrapper), C-R282-03 (DW10 compared arrays with themselves) (1×). **Added marker, data attribute or class pinned by a repo-scan test (D-29z736):** when a task adds such a token (not only removes or renames one), B greps it across every test root (`app/**/__tests__`, `perf/**`, `e2e/**`) as a claims `SWEEP` and puts every hit file in the covering set; a folder-local "scanner" list is not the sweep. 24. **Same pre-existing clause in every measurement row.** If one row says "listed with its ref result" for a failure that is identical in ref, every sibling measurement row (contrast, visibility, boxes) says the same or names the element as its target. Evidence: C-R202-02 failed CONTRAST on a ref-identical button while RING-VISIBLE listed the same class (1×).
29. **Every claim about current code is a tagged, re-runnable claim (claims block).** Each task sentence that states a fact about current code (a line, attribute, branch, timeout, testid, accessible name, a state recipe, a signal's render condition) ends with a tag `[K#]`; the task's `claims` block gives, per tag, the exact command (a grep with its root folders, or a baseline browser probe script) and its expected output (hit count or lines). C re-runs every command verbatim at HEAD (a mismatch is a planning FAIL) and runs `grep -nE 'l\.[0-9]+|(app|perf|docs)/[^ `]+|data-testid|aria-[a-z-]+' <task>` over the task; a hit that states a fact about a file under `store/` without a tag is a planning FAIL. References to loop artifacts (`tasks/`, `a-`/`b-`/`c-round-*`, `gates/`, `retros/`, `lessons.md`) are exempt. Claim types: the render branch of every named liveness or acceptance signal, and the task's state must satisfy that branch (A-R214-DEV-RANGE-LIVE: `[data-range-end]` renders only for all-tracks ranges); every state recipe, run once by B in the browser at the baseline (C-N229-S3-METHOD: Escape does not clear a time selection here, an empty-lane click does); premises about code (B-R230-APPLY-DESCRIBEDBY, C-R233-01 + A STOP 233, A-R254-WRONG-TIMEOUT-PREMISE, INFO-C253-ESCAPE-NO-STOP), including a ruling written in prose that rests on current behaviour ("setting a range always writes its own status"): tag it and probe it at the baseline (C-R272-01, C-R273-01; RC-R272-UNPROBED-PREMISE, 2×); a measured bound ("no more than HEAD"): the HEAD measurement is the claim (C-R254-01, L3); a changed meaning: when a command's source changes (position, unit, target), every readout that names the old source is a consumer (acceptance) row; grep the old word over `app/**` inline JSX, titles and aria, never one strings file (C-R250-01); a removed or constant-ed accessible name or state names its programmatic replacement with a row, or a ruling why none is needed (C-R256-01). Rename, remove and meaning sweeps use the roots `app/**` and `perf/**` (plus any e2e folder) (C-R258-01); a tagged command whose root is too narrow re-runs green, so C also checks every sweep's root against this list. A doc-line reference inside a "stays as written" protection clause is a fact about a file and gets a tag (C-R281-01, 1×). K1 (HEAD) is read at dispatch; a root-only commit after planning that leaves `git diff <planned> HEAD -- app` empty is accepted with a note, not a planning FAIL (INFO-C268-HEAD-DRIFT, 1×). Why rewritten: three clause additions in 245–259 left 5 claim findings against a baseline of 2 (retro-260 §8, `consequence-tester`).

50. **Focus origins are enumerated by grep, never sampled.** For any task where focus moves or the focused element can unmount, B runs one regex over the files the task grants plus, found by grep, the callers of every action that can remove the focused element (e.g. `undo\(\)|redo\(\)`), never a hand-picked list and never the whole folder (206 hits): `onPointerDown(Capture)?|onBlur|settleEditor\(|\.focus\(|^\s*\{[^}]*(\.map\(|&&|\?)`. Evidence: the grid-menu chain 241 FAIL → 242 → 243 → 244 found one new origin class per round; B-R243-UNDO-MARKER-FOCUS (retro-245 §3; `tech-lead`, `consequence-tester`) (4×); C-R245-03 (regex fix, 1×).
