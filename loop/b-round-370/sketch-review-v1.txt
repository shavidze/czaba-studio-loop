**Findings**

1. **Medium – comparator maintenance hazard, in two places (StudioWorkspace.tsx:738-753 and :800-821).**
   - The props type comes from `ComponentProps<typeof ArrangementGroupHeader>`. A new leaf prop flows into the wrapper's type but not into the hand-written `&&` chain, so it is silently ignored and the header renders stale. That is a wrong-UI bug, not just a performance one.
   - `sameTrackGroupOverviewClips` lists the four fields by hand, so a fifth field added to `TrackGroupOverviewClip` would be ignored the same way.
   - **Smallest guard, checked at compile time with no type assertion:** a mapped equality table that tsc refuses if any key is missing. Default everything to `Object.is`, and override only `overviewClips` and `activeCandidateTrackIds`:
     ```ts
     type PropEquality<P> = { [K in keyof P]-?: (a: P[K], b: P[K]) => boolean };
     const GROUP_HEADER_PROP_EQUALITY: PropEquality<ArrangementGroupHeaderWithSelectionProps> = { group: Object.is, /* …all 15… */ };
     ```
     Run it with a generic `for (const key in table)` helper. Please confirm that helper compiles under strict mode without a cast. If it does not, a bare `Record<keyof ArrangementGroupHeaderWithSelectionProps, true>` constant placed next to the explicit chain still forces whoever adds a prop to look at it.
     - **Do not** iterate `Object.keys(next)`: getting typed keys that way needs an assertion, which the project rules ban.
   - For the clip fields, a similar `Record<keyof TrackGroupOverviewClip, true>` placed next to `sameTrackGroupOverviewClips` is enough.
   - I would not use a runtime test as the main guard.
