# ყიდვის პროცესი (Add to Cart / Buy Now)

## User Story: უწყვეტი და მოქნილი ყიდვის პროცესი

როგორც მომხმარებელი, რომელიც იმყოფება პროდუქტის გვერდზე,
მინდა მქონდეს ორი მკაფიო არჩევანი: **"Add to Cart"**, რათა გავაგრძელო სხვა პროდუქტების თვალიერება, და **"Buy Now"**, რათა დაუყოვნებლივ გადავიდე გადახდის გვერდზე,
**So that I can** დავასრულო შენაძენის პროცესი ჩემთვის ყველაზე მოსახერხებელი გზით – იქნება ეს ერთი პროდუქტის სწრაფად ყიდვა, თუ რამდენიმე პროდუქტის ერთიანად შეძენა.

---

## ფუნქციონალის დეტალური აღწერა (Acceptance Criteria):

### სცენარი 1: მომხმარებელი აჭერს "Add to Cart"

1.  **მოქმედება:** მომხმარებელი აჭერს "Add to Cart" ღილაკს.
2.  **ინტერფეისის რეაქცია:**
    *   ღილაკი დროებით იცვლის სტატუსს (მაგ., აჩვენებს მბრუნავ ინდიკატორს), რათა მომხმარებელმა დაინახოს, რომ პროცესი მიმდინარეობს.
    *   წარმატების შემთხვევაში, ეკრანზე ჩნდება მოკლე შეტყობინება (Toast Notification), მაგალითად: **"'Middle East Songs Pack' დაემატა კალათაში."**
    *   საიტის ჰედერში, კალათის იკონკაზე, ციფრი იზრდება ერთით, რაც აჩვენებს კალათაში არსებული პროდუქტების რაოდენობას.
3.  **ტექნიკური ლოგიკა (Behind the Scenes):**
    *   ფრონტენდი აგზავნის მოთხოვნას Backend API-სთან.
    *   მოთხოვნა შეიცავს პროდუქტის უნიკალურ `variantId`-ს.
    *   Backend ამატებს ამ პროდუქტს მომხმარებლის მიმდინარე კალათაში (ან ქმნის ახალ კალათას, თუ ის ცარიელი იყო).
4.  **საბოლოო მდგომარეობა:** მომხმარებელი რჩება პროდუქტის გვერდზე და შეუძლია გააგრძელოს საიტზე ნავიგაცია.

### სცენარი 2: მომხმარებელი აჭერს "Buy Now"

1.  **მოქმედება:** მომხმარებელი აჭერს "Buy Now" ღილაკს.
2.  **ინტერფეისის რეაქცია:**
    *   ღილაკი იცვლის სტატუსს (აჩვენებს მბრუნავ ინდიკატორს).
3.  **ტექნიკური ლოგიკა (Behind the Scenes):**
    *   ფრონტენდი აგზავნის მოთხოვნას Backend API-სთან, რომ შექმნას ახალი კალათა **მხოლოდ ამ ერთი პროდუქტით**.
    *   Backend-დან პასუხად ვიღებთ კალათის ობიექტს, რომელიც შეიცავს უნიკალურ `checkoutUrl`-ს.
    *   ჩვენი აპლიკაცია **დაუყოვნებლივ გადაამისამართებს (redirects)** მომხმარებელს ამ `checkoutUrl`-ზე.
4.  **საბოლოო მდგომარეობა:** მომხმარებელი გადადის Stripe-ის დაცულ გადახდის გვერდზე, სადაც ის ავსებს თავის მონაცემებს და ასრულებს ტრანზაქციას.

---

## ტექნიკური მოთხოვნები:

### "Add to Cart" ღილაკის ლოგიკა:
*   ღილაკზე დაჭერისას, გამოიძახე Backend API-ს cart endpoint.
*   გადაეცი პროდუქტის შესაბამისი `variantId`.
*   წარმატებული პასუხის შემთხვევაში:
    *   აჩვენე წარმატების შეტყობინება (Toast Notification).
    *   განაახლე კალათის მდგომარეობა (state), რათა ჰედერში არსებულმა იკონკამ განახლებული რაოდენობა აჩვენოს.

### "Buy Now" ღილაკის ლოგიკა:
*   ღილაკზე დაჭერისას:
    *   გამოიძახე Backend API-ს checkout endpoint.
    *   წარმატებული პასუხიდან ამოიღე `checkoutUrl`.
    *   გამოიყენე `window.location.href` მომხმარებლის ამ `checkoutUrl`-ზე გადასამისამართებლად.

გთხოვ, უზრუნველყო მომხმარებლის კარგი გამოცდილება ღილაკების მდგომარეობების (loading, success, error) მართვით.
