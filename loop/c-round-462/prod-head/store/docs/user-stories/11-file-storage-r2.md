# ფაილების შენახვა (Cloudflare R2)

ზუსტად ის მოდელი უნდა გამოვიყენოთ, რაც სტანდარტულია: **Product Variants (პროდუქტის ვარიანტები)**.

---

## Cloudflare R2-ის სტრუქტურა

ახლა შენს `middle-east` ფოლდერს უნდა დაამატო ახალი განყოფილება: **Downloads**.
შენი სტრუქტურა R2-ზე საბოლოოდ ასეთი იქნება:

```text
middle-east/
│
├── Studio-Assets/           <-- (ეს უკვე გაქვს: სარედაქციო MP3-ები სტუდიისთვის)
│   ├── drums.mp3
│   ├── bass.mp3
│   └── ...
│
└── Downloads/               <-- (ახალი: ეს არის გასაყიდი ZIP ფაილები)
    ├── Standard-Pack.zip    (შეიცავს მხოლოდ Full Mix-ს, MP3/WAV)
    └── Stems-Pack.zip       (შეიცავს ყველა ინსტრუმენტს ცალ-ცალკე, High Quality WAV)
```

---

## როგორ მუშაობს "დაყოფა" (Mapping Logic)

აქ არის მთავარი ტრიუკი. შენ გჭირდება ლოგიკა, რომელიც იტყვის: *"თუ იყიდა ვარიანტი A, მიეცი ფაილი X. თუ იყიდა ვარიანტი B, მიეცი ფაილი X და Y + სტუდია"*.

### A. მომენტალური გადმოწერა

*   **თუ იყიდა "Standard License" (Variant ID: 111):**
    *   გაუგზავნე ლინკი: `.../middle-east/Downloads/Standard-Pack.zip`
*   **თუ იყიდა "Premium License" (Variant ID: 222):**
    *   გაუგზავნე ლინკი 1: `.../middle-east/Downloads/Standard-Pack.zip`
    *   გაუგზავნე ლინკი 2: `.../middle-east/Downloads/Stems-Pack.zip`

### B. სტუდიაზე წვდომა (React App)

შენს სტუდიაში შესვლისას, სისტემამ უნდა შეამოწმოს, რა იყიდა მომხმარებელმა.

1.  მომხმარებელი შედის: `mysite.com/studio/middle-east`
2.  შენი საიტი ამოწმებს: *"აქვს ამ იუზერს ნაყიდი `middle-east`-ის **Premium** ვარიანტი?"*
3.  **თუ კი:**
    *   იტვირთება `Studio-Assets` ფოლდერიდან MP3-ები.
    *   იხსნება რედაქტორი.
4.  **თუ არა (ან მხოლოდ Standard აქვს):**
    *   გამოდის შეტყობინება: *"სტუდიის გამოსაყენებლად გჭირდებათ Premium ლიცენზია. განაახლეთ ახლავე!"*

## შეჯამება

შენ არ გჭირდება ორი სხვადასხვა პროდუქტი.
შენ გჭირდება **3 ფოლდერი** R2-ზე და **2 ვარიანტი** Backend-ში.

1.  **Standard Buyer** -> იღებს მხოლოდ `Downloads/Standard-Pack.zip`.
2.  **Premium Buyer** -> იღებს ZIP-ებს **+** უფლებას, რომ React აპლიკაციამ წაიკითხოს `Studio-Assets` ფოლდერი.
