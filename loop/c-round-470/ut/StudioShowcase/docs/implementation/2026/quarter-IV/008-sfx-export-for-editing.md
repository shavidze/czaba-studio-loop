# SFX Export for Editing

**თარიღი:** 2026-10-03
**სტატუსი:** Completed

## კონტექსტი

Scene Builder-ში გამზადებული ხმები უნდა გადავიდეს Premiere Pro-ში, DaVinci Resolve-ში ან სხვა ვიდეორედაქტორში. მომხმარებელი ირჩევს ერთ გაერთიანებულ WAV-ს ან ცალკეულ ხმებს ერთ ZIP-ში. Universal წვდომის არსებული შემოწმება უცვლელია; დამატებითი ფასიანი იარუსი არ დამატებულა.

## მიდგომა

Export audio ხსნის ფიქსირებულ სამუშაო პანელს სამი არჩევანით. One combined WAV ინარჩუნებს მთელი სცენის ხანგრძლივობას და ზუსტად იმავე PCM-ს, რომელსაც Studio უკრავს. Separate sounds · Video sync თითო ხმას აძლევს სცენის სრულ ხანგრძლივობას, საწყისი და ბოლო სიჩუმით; ყველა WAV ვიდეორედაქტორში ნულოვან წამზე უნდა განთავსდეს. Separate sounds · Used segments იწყება თავად ხმის პირველი ნიმუშიდან და შეიცავს მის გამოყენებულ სიგრძეს, Loop-ის ჩათვლით.

ყველა ვარიანტი იყენებს ორიგინალ PCM ჩანაწერებს, საერთო sample rate-ს, stereo 24-bit WAV-ს, იმავე Trim, Gain, Fade, Pan და რბილ Loop-ს. Mute/Solo განსაზღვრავს რომელი ხმები შევა ცალკეულ ფაილებში. ZIP-ის ფაილების სახელები შეიცავს სცენას, ხმის სახელსა და უნიკალურ რიგის ნომერს. ექსპორტამდე ჩანს ფაილების სია, რაოდენობა და ხანგრძლივობა.

ცალკეული 24-bit ფაილების დამოუკიდებელი დამრგვალების გამო მათი ჯამისა და ერთჯერადად დამრგვალებული გაერთიანებული WAV-ის მაქსიმალური დაშვებული განსხვავებაა თითო ფაილზე ერთი უმცირესი PCM ერთეული. სამი რეალური Shopping Mall ჩანაწერის ტესტში განსხვავება მხოლოდ ერთ ასეთ ერთეულს შეადგენს; დამუშავება და დროები ემთხვევა.

## არქიტექტურა

არსებული renderer-ის generator ასრულებს იმავე გამოთვლებს და აბრუნებს რეალურ პროგრესს დამუშავებული ნიმუშების მიხედვით. ჩვეულებრივი მოსმენა generator-ს სინქრონულად ასრულებს; ექსპორტი მუშაობს ცალკე Web Worker-ში. WAV encoding-ის პროგრესი იზომება ჩაწერილი ნიმუშებით, ZIP-ის დასრულება — მომზადებული ფაილებით. Cancel და პანელის დახურვა Worker-ს წყვეტს; შეცდომა და გაუქმება სცენის ისტორიას არ ცვლის.

Worker-ის შექმნამდე გამოითვლება ექსპორტისთვის დამატებით საჭირო მეხსიერება: არჩეული აუდიოს ასლები, სცენის/ცალკეული ხმის buffer-ები და WAV/ZIP ასლები. 512 MiB-ის გადაჭარბებისას მომხმარებელს ეძლევა კომპაქტური რეჟიმის ან მოკლე სცენის არჩევის მითითება. ეს დამატებითი სამუშაოს შეფასებაა; Studio-ში უკვე არსებული cache ცალკე რჩება.

Worker იღებს მხოლოდ სცენაში გამოყენებული source მონაკვეთების ახალ ასლებს. მათი buffer-ების transfer არ ეხება ორიგინალებს. Integer sourceStartFrame ინარჩუნებს აუდიოს საწყის პოზიციას; scene JSON-ის ზუსტი დროები არ იცვლება, მათ შორის 44.1 kHz-ის მილიწამიანი არჩევანი. კომპაქტური ექსპორტი თითოეულ ხმაზე მხოლოდ გამოყენებული სიგრძის buffer-ს ქმნის. ZIP იქმნება fflate-ის uncompressed streaming ZIP-ით.

## შეცვლილი ფაილები

- `SfxSceneExport.tsx` — არჩევანი, სია, პროგრესი, გაუქმება და შეცდომა; native dialog, ფიქსირებული header/footer, შიგნით მოძრავი შინაარსი და reduced Motion.
- `SfxSceneBuilder.tsx` — საერთო ექსპორტის პანელის გახსნა.
- `sfx-export.ts` — ფაილების გეგმა, სახელები, მეხსიერების შეფასება, WAV და ZIP მომზადება.
- `sfx-export.client.ts`, `sfx-export.worker.ts` — Worker transport და უსაფრთხო დასრულება/გაუქმება.
- `sfx-scene.ts`, `sfx-edit.ts` — საერთო renderer-ის რეალური პროგრესი, კომპაქტური ხმის buffer და source frame origin.
- `sfx-export.test.ts` — აუდიო, ZIP, დროები, წყაროს სიზუსტე, ხელმისაწვდომობა და გაუქმება.
- `package.json`, `package-lock.json` — fflate ZIP dependency.
- `vitest.config.ts` — ერთდროულად მაქსიმუმ ოთხი worker, სრული JSDOM/აუდიო შემოწმების სტაბილური დატვირთვისთვის.

## პრობლემები და გადაწყვეტები

გადატვირთული mix-ის clipping ცალკეული WAV-ების შეკრებით არ მეორდება → გაერთიანებული WAV კვლავ ემთხვევა მოსმენას და აფრთხილებს დონეზე; ცალკეული ფაილების ექსპორტი ითხოვს დონის შემცირებას, სცენის დაკარგვის გარეშე.

გრძელი ორიგინალების სრული ასლები Worker-ში ზედმეტ მეხსიერებას მოითხოვდა → იგზავნება მხოლოდ გამოყენებული source ფანჯარა; ზედმეტად დიდი სამუშაო ჩერდება ასლების შექმნამდე.

Source დროების მილიწამზე დამრგვალება არღვევდა 44.1 kHz-ის მოკლე არჩევანის ვალიდაციას → JSON-ის დროები რჩება უცვლელი და integer frame origin მხოლოდ აუდიოს ასლს ერთვის.

სრული suite-ის ერთდროული JSDOM/PCM ტესტები დროის ლიმიტში ვერ ეტეოდა, ცალკეული გაშვებები კი გადიოდა → შემოიფარგლა ერთდროული worker-ების რაოდენობა; ტესტების მოლოდინის დრო და აუდიოს სიზუსტის შემოწმებები არ შესუსტებულა.

მობილურზე ბოლო ღილაკები შეიძლებოდა პანელს გასცდენოდა → header/footer ფიქსირებულია, ცენტრალური ნაწილი დამოუკიდებლად მოძრაობს. არჩევანისა და პროგრესის ცვლილება გვერდს არ გადაადგილებს.

## ტესტირება

Unit ტესტები ხსნის ZIP-ს, ამოწმებს 30-წამიან სცენას სამი ხმით, საწყის სიჩუმეს, 12/25 წამზე მოთავსებას, სხვადასხვა sample rate-ს, Fade/Pan/Loop-ის იდენტურობას კომპაქტურ და სინქრონულ ფაილებში, Mute/Solo-ს, 12 გადაფარულ ხმას და უსაფრთხო უნიკალურ ქართულ სახელებს. გაერთიანებული WAV-ის ყველა ნიმუში ემთხვევა preview PCM-ს.

შემოწმებულია source ფანჯრის ზუსტი ასლი, 44.1 kHz-ის 1 ms არჩევანი და ნახევარი არჩევანის crossfade, გადატვირთული mix-ის უარყოფა ZIP-ისთვის, მეხსიერების უარყოფა Worker-მდე, გაუქმება, ხელახლა ცდა და Worker-ის შეცდომის შემდეგ cleanup. არსებული Scene/Quick Edit/Video Sync ტესტები შენარჩუნებულია.

Shopping Mall-ის რეალური 96 kHz/24-bit ორიგინალებიდან შეიქმნა 30-წამიანი WAV და ორი ZIP. სამი სინქრონული WAV-ის ჯამის განსხვავება იყო 1/8388608; გაერთიანებული WAV preview-ს ზუსტად დაემთხვა. ბრაუზერში გამოიყენება სატესტო account API, რეალური Worker და WAV/ZIP decoding; Production ანგარიშის სცენის შესანახი API ამ ცვლილებაში არ შეცვლილა.

რეალურ ბრაუზერში სამივე ექსპორტის რეჟიმი დასრულდა. 300-წამიანი სცენის აქტიური მომზადების Cancel-მ Worker შეწყვიტა, ჩამოტვირთვა არ წარმოქმნილა და სამივე ხმა დარჩა. 390×844 ეკრანზე შინაარსის სიგანეა 390px, dialog-ის 759px სიმაღლეში header და Download/Cancel ხილულია; console-ში შეცდომა არ დაფიქსირებულა.
